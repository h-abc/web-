1. 竞态条件处理
   - 场景：用户对已结束的比赛提交预测。
   - 实现：POST /api/predictions 首先检查比赛状态，若为 FINISHED 则返回 HTTP 409 Conflict，
     前端收到 409 后提示用户“比赛已结束，无法预测”，阻止写入。
   - 数据库使用 WAL 模式避免读写冲突。
2. 性能优化
   - 静态赛事数据保存在前端，无需额外网络请求即可渲染所有比赛页面。
   - 预测和评论通过 RESTful API 按需加载，不阻塞首次渲染。
   - SQLite 预编译查询，评论列表限制返回 50 条。
   - Docker 镜像基于 Alpine，体积小，启动快。
3. 容灾与持久化
   - 数据库文件挂载至宿主机，容器崩溃或删除后数据不丢失。
   - 后端使用 restart: unless-stopped 策略，异常退出自动重启。
